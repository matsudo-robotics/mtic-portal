# M-TIC職員ポータル（mtic-portal）v2.3

NPO法人松戸技術革新センターM-TIC の職員専用ポータルです。
アイコンが並んだホームから、団体の仕事に使うアプリ（タスカー・入退室・チャット・機材・在庫・レジ・受発注・帳票・オンラインショップなど）を使えます。
v2.1 から、お客さま向けの **M-TICオンラインショップ**（`shop/`・いまは「準備中」）が付属しています。
v2.3 から、今までの入退室の **Googleフォーム** の回答（過去の分も）が、ポータルの入退室の記録・在室ボードに入ります（「入退室 → Googleフォーム」でつなぐ）。
v2.2 から、職員・管理者・責任者のサインインは **パスワード＋スマホの認証アプリの6けたのコード（2段階認証）** になり、タブやブラウザを閉じると自動でサインアウトします。

- 画面：`index.html` 1枚（全部のアプリ入り）＋ `vendor/`（カメラ読み取り・QR作成の部品）＋ `shop/`（お客さま向けのショップ）を GitHub Pages に置く
- サインイン・保存：Firebase（無料の Spark プラン）
- メール通知・チャットのファイル保存・ショップの注文の受付：裏方GAS（`notify.gs`・画面なし）

## 守り方の考え方

- このリポジトリのファイルは誰でも見られる前提です。パスワード・個人情報・フォームのURL・振込先は書きません（振込先などは「設定」から入れて、会員だけが見られる場所に保存します）。
- データは Firebase のルールで「会員名簿にいる有効な人だけ」読めます。役割（責任者・管理者・職員・キオスク・裏方）で書けるものを分けています。
- パスワードはこちらでは保存しません（Firebaseが元に戻せない形で保管）。
- 職員・管理者・責任者は **2段階認証（認証アプリの6けたのコード・TOTP）が必須** です（はじめてのサインインで登録。キオスクと裏方の自動処理は使いません）。パスワードが漏れても、スマホのアプリがなければ入れません。スマホのデータ（連絡先・写真など）は送りません。
- サインインは「このタブだけ」に保存します（タブ・ブラウザを閉じるとサインアウト。端末にサインインもデータの写しも残しません）。キオスク用アカウントの端末だけは、再起動しても使えるように端末に残します。
- IDカードのQRには長いランダムな文字が入り、キオスクはその指紋（SHA-256）で本人を調べます。
- チャットのファイルは団体のドライブの非公開フォルダに入り、チャンネルに入れる人だけが取り出せます。
- 検索エンジンに載らないよう、ポータルには `noindex` を入れています（ショップはお客さま向けなので入れていません）。
- ショップのお客さまの注文は、裏方GASが中身・在庫・金額を確かめてから入れます。ページ（ブラウザ）から直接は書けません。注文は職員だけが見られます。
- ショップに公開されるのは、お店の設定・表記と「載せた商品」（名前・値段・説明・写真・在庫の目安）だけです。仕入値・保管場所・実際の在庫の数は出ません。

## アップデートのしかた

1. 新しい `index.html`（と、変わっていれば `vendor/`）を GitHub にアップロードして上書き（`config.js` はそのまま）
2. ルール（`firestore.rules`）や裏方GAS（`notify.gs`）の版が上がったときは、それぞれ貼り直す
3. 1〜2分後にポータルを再読み込みして、ホームの右下の版番号と「設定・診断 → 診断」で確認

### v2.2 から v2.3 に上げるとき（1回だけ）

1. 裏方GASを `notify.gs`（v2.2）に貼り替えて保存 → エディタで `checkSetup` を実行して「許可」（フォームを読む許可が増える）→「デプロイを管理」→ 新しいバージョンでデプロイ（URLは変わらない）
2. `index.html` をアップロード（`config.js`・`vendor/`・`shop/`・ルールはそのまま）
3. ポータルの「入退室 → Googleフォーム」（責任者・管理者）→「フォームを探す」→ 入退室のフォームの「これにつなぐ」→ 名簿と合わない名前があれば会員を選ぶ

### v2.1 から v2.2 に上げるとき（1回だけ）

1. 責任者が Google Cloud Shell で、認証アプリ（TOTP）の方式を有効にする（手順シート「4-5」。Firebase は無料プランのまま）
2. `index.html` と `shop/` フォルダをアップロード（`config.js`・`vendor/` はそのまま。ルールと裏方GASは v2.1 のまま）
3. 各自、次のサインインで2段階認証を登録（責任者が先に。予備の登録もおすすめ）

### v2.0 から v2.1 に上げるとき（1回だけ）

1. Firebase のルールを `firestore.rules`（v2.1）に貼り替えて「公開」
2. `index.html` と `shop/` フォルダをアップロード（`config.js`・`vendor/` はそのまま）
3. 裏方GASを `notify.gs`（v2.1）に貼り替え →「デプロイを管理」→ 新しいバージョンでデプロイ（URLは変わらない）→ エディタで `setupTriggers` をもう一度実行（1時間ごとの在庫そろえが入る）
4. 「設定・診断 → 初期データ」で「オンラインショップ」を入れる（準備中の設定・表記の見本・チャットの「ショップのお知らせ」）→「診断」で全部 OK（裏方GASが v2.1）を確認
5. お店は「準備中」のまま。公開するときは「オンラインショップ → お店の設定・表記」で表記を見直し、「公開の前に」が全部 ✓ になってから

### v1.0 から v2.0 に上げるとき（1回だけ）

1. Firebase のルールを `firestore.rules`（v2.0）に貼り替えて「公開」
2. `index.html` と `vendor/` フォルダをアップロード（`config.js` はそのまま。v2.0 の項目を足すときは同梱の `config.js` を見本に）
3. 裏方GASを `notify.gs`（v2.0）に貼り替え →「デプロイを管理」→ 新しいバージョンでデプロイ（URLは変わらない）→ 裏方アカウント（BRIDGE_EMAIL / BRIDGE_PASSWORD）をスクリプトプロパティに設定
4. 責任者がサインインして「会員管理」を開く（名前の一覧が自動でそろい、v1.0 のカード用の文字が消える）
5. 「設定・診断 → 初期データ」で機材・品目・チャンネルなどを入れる → 「診断」で全部 OK を確認
6. IDカードを発行し直す（v1.0 のコードは使いません）

## アイコンを増やすとき

`config.js` の `EXTRA_APPS` に1行足し、リンク先はサインイン後に管理者が「リンク設定」から入れます（HTMLに書かずに済む）。

```js
EXTRA_APPS: [ { id: 'form1', name: '○○フォーム', section: 'daily', icon: 'link' } ]
```

## オンラインショップ（shop/）

- お客さま向けのURL：`https://matsudo-robotics.github.io/mtic-portal/shop/`
- いまは「準備中」。ポータルの「オンラインショップ」の「お店のページ」から開くと、職員はプレビューとテスト注文ができます（サインインはタブごとなので、URLやブックマークから開いたタブでは、お客さまの見え方になります）
- 商品を載せる・値段を決める・注文に対応する・公開／準備中を切り替える：ポータルの「オンラインショップ」
- 注文の流れ：お客さまが注文 → 裏方GASが確かめて受け付け（お客さまに確認メール・お店に知らせ・チャットに流れる）→ 職員が在庫と送料を確かめて、ポータルからお支払いのご案内を送る → 入金確認 → 出庫して発送／受け渡し → 完了
